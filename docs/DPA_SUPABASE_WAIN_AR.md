## 1️⃣ المقدمة والأطراف

### الطرف الأول: متحكم البيانات (Data Controller)
- **الاسم:** WAIN App
- **الدولة:** المملكة العربية السعودية
- **البريد الإلكتروني:** support@wainapp.sa
- **الدور:** جمع البيانات مباشرة من المستخدمين + اتخاذ قرارات معالجة البيانات

### الطرف الثاني: معالج البيانات (Data Processor)
- **الاسم:** Supabase Inc
- **الموقع:** San Francisco, USA
- **الموقع الجغرافي للخوادم:** Asia-Pacific Region (Singapore/Tokyo)
- **الدور:** تخزين البيانات بشكل آمن + معالجة الاستعلامات + إدارة النسخ الاحتياطية

### البيانات الموضوع (Data Subjects)
- **من:** مستخدمو تطبيق WAIN
- **الحقوق:** الوصول، التصحيح، الحذف، النقل، الاعتراض (وفقاً لـ PDPL)

## 2️⃣ نطاق المعالجة

### أ. أنواع البيانات المعالَجة

| فئة البيانات | التفاصيل | الحساسية |
|-----------|---------|--------|
| **بيانات الحساب** | البريد الإلكتروني، اسم المستخدم، كلمة المرور (مشفرة) | 🔴 عالية |
| **البيانات الشخصية** | صور الأغراض، الأوصاف، المواقع | 🟠 متوسطة |
| **البيانات المالية** | الفواتير، الإيصالات، التكاليف، الضمانات | 🔴 عالية جداً |
| **بيانات الاشتراك** | تواريخ التجديد، تكاليف الاشتراكات | 🟠 متوسطة |
| **معرفات الأجهزة** | Device ID، نوع النظام، إصدار التطبيق | 🟡 منخفضة |
| **سجلات الوصول** | عنوان IP، نوع المتصفح، أوقات الوصول | 🟡 منخفضة |
| **نتائج التحليل** | نتائج OCR من الفواتير (عند استخدام OpenAI) | 🔴 عالية |

### ب. الغرض من المعالجة

1. **توفير الخدمة (Primary Purpose)**
   - تخزين بيانات المستخدمين
   - معالجة الاستعلامات من التطبيق
   - المصادقة والتفويض
   - ضمان توفر الخدمة

2. **الأمان والحماية**
   - منع الاستخدام غير المصرح به
   - اكتشاف التهديدات الأمنية
   - منع الاحتيال
   - الامتثال للمتطلبات القانونية

3. **تحسين الخدمة (Legitimate Interest)**
   - تحليل الأداء
   - إصلاح الأخطاء
   - تطوير ميزات جديدة
   - (بدون تدريب نماذج AI - ✅ مصرح به)

### ج. مدة المعالجة

- **المدة الأساسية:** طول فترة اشتراك المستخدم في التطبيق
- **مدة النسخ الاحتياطية:** 30 يوماً بعد حذف الحساب
- **مدة سجلات التدقيق:** سنتان (حسب متطلبات الأمان)
- **مدة الحذف النهائي:** 30 يوماً من طلب الحذف

### د. الموقع الجغرافي

- **الخوادم الأساسية:** منطقة آسيا والمحيط الهادئ (سنغافورة/طوكيو)
- **النسخ الاحتياطية:** نفس المنطقة (آسيا والمحيط الهادئ)
- **المراكز الجغرافية:** لا نقل خارج منطقة آسيا والمحيط الهادئ بدون موافقة صريحة

## 4️⃣ تدابير أمان البيانات

### أ. التشفير

#### التشفير في الانتقال (In Transit)
```
✅ بروتوكول: TLS 1.3 أو أعلى
✅ الشهادات: موقعة من جهة موثوقة
✅ المنافذ: 443 (HTTPS) فقط
✅ الخوادم: لا تقبل اتصالات HTTP غير آمنة
```

#### التشفير أثناء التخزين (At Rest)
```
✅ الخوادم: AES-256 bit encryption
✅ كلمات المرور: Argon2id hashing (Supabase default)
✅ البيانات الحساسة: مشفرة في قاعدة البيانات
✅ النسخ الاحتياطية: مشفرة بنفس المستوى
```

### ب. أمان قاعدة البيانات

#### Row Level Security (RLS) - تطبيق شامل
```sql
-- مثال من WAIN:
-- جدول المشاريع
CREATE POLICY "Users can view their own projects"
  ON projects FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can only update their own projects"
  ON projects FOR UPDATE
  USING (auth.uid() = user_id);

-- جدول الفواتير المالية
CREATE POLICY "Users can view their financial documents"
  ON financial_documents FOR SELECT
  USING (auth.uid() = user_id);
```

**النتيجة:** كل مستخدم يرى فقط بيانته الخاصة

#### تفويض الوصول (Authentication & Authorization)
```
✅ JWT Tokens (JSON Web Tokens)
✅ التحقق من التوقيع: private key من Supabase
✅ انتهاء الصلاحية: قابل للتكوين (افتراضي 24 ساعة)
✅ التجديد التلقائي: عند إعادة الاتصال
✅ إلغاء الجلسة: فوري عند تسجيل الخروج
```

#### مفاتيح API الآمنة
```
✅ Anon Key (عام): للعمليات المصرح بها فقط (SELECT مع RLS)
✅ Service Role Key (خاص): للعمليات الإدارية فقط (Edge Functions)
✅ لا يوجد مفتاح سري في التطبيق النقال
✅ جميع المفاتيح محمية في .env
```

### ج. حماية التطبيق

#### CORS (Cross-Origin Resource Sharing)
```
✅ السياسة الحالية: تقبل جميع التطبيقات (آمن لأن JWT مطلوب)
✅ في المستقبل: تقيد على نطاقات معروفة
```

#### معالجة الأخطاء
```
✅ لا تكشف الأخطاء الحساسة للمستخدمين
✅ رسائل خطأ عامة (مثل: "خطأ في الخادم")
✅ تسجيل تفاصيل الخطأ في السجلات الداخلية فقط
✅ عدم تسريب أسماء الجداول أو الأعمدة
```

### د. سياسات RLS الكاملة

```sql
-- جميع الجداول في WAIN مع RLS:

1. profiles - حماية بيانات الحساب الشخصية
2. projects - حماية مشاريع المستخدم
3. generated_articles - حماية المقالات المولدة
4. rewrites - حماية النصوص المعادة
5. summaries - حماية الملخصات
6. user_credits - حماية أرصدة المستخدم
7. credit_transactions - حماية سجل العمليات
8. subscriptions - حماية حالة الاشتراك
9. financial_documents - حماية الوثائق المالية ⭐
10. audit_logs - حماية سجلات التدقيق
11. video_projects - حماية المشاريع المرئية
12. voice_profiles - حماية ملفات الصوت
```

## 5️⃣ حقوق المستخدمين

### أ. حق الوصول (Right of Access)

**الالتزام:** تقديم نسخة من بيانات المستخدم عند الطلب

```
عملية الطلب:
1. المستخدم يدخل إلى Settings > Privacy > Export My Data
2. النقر على "Export Data"
3. التحقق عبر البريد الإلكتروني
4. Supabase Edge Function يجمع البيانات
5. إرسال رابط تحميل آمن للمستخدم
6. صيغة التصدير: JSON (قابل لقراءة الآلة)
7. مدة التسليم: أقل من 24 ساعة
```

**محتوى الملف المُصدّر:**
```json
{
  "profile": {
    "email": "user@example.com",
    "username": "username",
    "created_at": "2024-01-01"
  },
  "projects": [...],
  "financial_documents": [...],
  "audit_log": [...],
  "consent_records": [...]
}
```

### ب. حق التصحيح (Right of Correction)

**الالتزام:** السماح بتصحيح البيانات غير الدقيقة

```
البيانات القابلة للتصحيح:
✅ البريد الإلكتروني: نعم (مع التحقق)
✅ اسم المستخدم: نعم
✅ اللغة والتفضيلات: نعم
✅ وصف الأغراض: نعم (من قبل المالك)

البيانات غير القابلة للتصحيح:
❌ تاريخ الإنشاء: بيانات سجلية
❌ سجل المعاملات المالية: بيانات تاريخية
❌ سجل التدقيق: للأمان
```

### ج. حق الحذف (Right to Erasure - "الحق في النسيان")

**الالتزام:** حذف بيانات المستخدم عند الطلب

```
عملية الحذف:
1. المستخدم: Settings > Privacy > Delete Account
2. تحذير: "سيتم حذف جميع البيانات نهائياً"
3. التحقق عبر البريد الإلكتروني
4. فترة الانتظار: 7 أيام (للتراجع)
5. عند انتهاء 7 أيام: حذف نهائي بدون استرجاع
6. مدة الحذف الكامل: 30 يوم (انتظار انتهاء النسخ الاحتياطية)

الاستثناءات القانونية (لا تُحذف):
⚠️ الفواتير: 7 سنوات (قانون الضريبة السعودي)
⚠️ سجل التدقيق: سنتان (متطلبات الأمان)
⚠️ أوامر قضائية: حفظ البيانات لأغراض قانونية
```

### د. حق النقل (Right to Data Portability)

**الالتزام:** تقديم البيانات بصيغة معروفة قابلة للنقل

```
الصيغ المتاحة:
✅ JSON: قابل لقراءة الآلة
✅ CSV: للبيانات المجدولة
✅ PDF: للقراءة البشرية

مثال (صيغة البيانات المصدرة):
{
  "format": "json",
  "version": "1.0",
  "export_date": "2026-11-14T10:30:00Z",
  "user": {...},
  "data": {...}
}
```

### هـ. حق الاعتراض (Right to Object)

**الالتزام:** السماح بـ opt-out من معالجة معينة

```
الخدمات القابلة للاعتراض:
✅ التحليلات: opt-out في Settings
✅ OpenAI Vision: خانة منفصلة في signup
✅ البريد الإلكتروني التسويقي: unsubscribe في كل رسالة

الخدمات غير القابلة للاعتراض (ضرورية):
❌ المصادقة والتفويض
❌ أمان الحساب
❌ معالجة الدفع
```

## 6️⃣ الاستجابة للحوادث الأمنية

### الالتزام: الإشعار خلال 72 ساعة

```
حالة خرق البيانات:

ت = 0 (اكتشاف الخرق):
  ├─ تفعيل فريق الاستجابة الفوري
  ├─ حجب الوصول غير المصرح به
  ├─ الحفاظ على الأدلة

ت = 1 ساعة:
  ├─ التقييم الأولي للضرر
  ├─ تحديد نطاق البيانات المتأثرة
  ├─ اتصال قانوني

ت = 24 ساعة:
  ├─ التحقيق الكامل
  ├─ جذر السبب
  ├─ خطة الاستجابة

ت = 72 ساعة (الموعد النهائي):
  ├─ إشعار المستخدمين المتأثرين
  ├─ إشعار السلطات (إذا لزم)
  └─ تحديث صفحة الحالة العامة
```

### محتوى الإشعار:

```
تنبيه أمني من WAIN:

نحن نعلمك بحادث أمني يؤثر على حسابك:

1. ماذا حدث: [وصف الحادث]
2. متى: [تاريخ ووقت الحادث]
3. ماذا تأثر: [أنواع البيانات]
4. ماذا نفعل: [الإجراءات المتخذة]
5. ماذا تفعل أنت: [الخطوات الموصى بها]

للمزيد: اتصل بـ privacy@wainapp.sa
```

### التزامات Supabase:
- ✅ إشعار WAIN فوراً عند اكتشاف خرق
- ✅ تقديم تقرير فني مفصل
- ✅ المساعدة في التحقيق
- ✅ توثيق كامل للحادث

## 8️⃣ الإنهاء والحذف الآمن

### الإنهاء العادي للاتفاق

```
عند انتهاء الخدمة:

1. فترة الإشعار المسبق: 30 يوماً
2. تصدير البيانات: خيار للمستخدمين
3. فترة الحفظ: 30 يوم (نسخ احتياطية)
4. الحذف النهائي: بعد 30 يوم من الإنهاء
```

### حذف البيانات الآمن

```
معايير الحذف الآمن:

✅ حذف من جميع النسخ في قاعدة البيانات
✅ حذف من النسخ الاحتياطية (بعد 30 يوم)
✅ حذف من CDN والذاكرة المؤقتة
✅ حذف من ذاكرة التخزين المؤقت في الجهاز
✅ عدم الاحتفاظ بنسخ الأرشيف
```

### شهادة الحذف

```
عند الانتهاء:
1. إصدار شهادة حذف رسمية
2. توقيع من Supabase
3. إرسالها إلى WAIN
4. الاحتفاظ بها في الملفات القانونية
```
