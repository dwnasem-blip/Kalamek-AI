## 3️⃣ تصنيف الحوادث الأمنية

### مستويات الخطورة

#### 🟢 **المستوى 1 (أخضر) - منخفض**
- **المقياس:** < 100 مستخدم متأثر + بيانات غير حساسة
- **الأمثلة:**
  - كشف معرفات الأجهزة العامة
  - تسريب أسماء المستخدمين (معروفة بالفعل)
  - أخطاء في السجلات (بدون بيانات شخصية)
- **الاستجابة:** إصلاح + تسجيل
- **الإشعار:** نعم (مباشر في التطبيق)
- **الإعلام:** أخبار عامة (اختياري)

#### 🟡 **المستوى 2 (أصفر) - متوسط**
- **المقياس:** 100-1000 مستخدم متأثر + بيانات معتدلة الحساسية
- **الأمثلة:**
  - تسريب عناوين بريد إلكترونية
  - إفصاح محدود عن بيانات الملفات الشخصية
  - وصول غير مصرح به لفترة قصيرة
- **الاستجابة:** احتواء + تحقيق + إصلاح
- **الإشعار:** بريد إلكتروني فوري
- **الإعلام:** صفحة الحالة + بيان صحفي

#### 🟠 **المستوى 3 (برتقالي) - عالي**
- **المقياس:** 1000+ مستخدم متأثر + بيانات حساسة
- **الأمثلة:**
  - تسريب كلمات مرور مشفرة
  - إفصاح عن بيانات مالية
  - وصول غير مصرح به لفترة طويلة
- **الاستجابة:** إجلاء فوري + استدعاء طارئ + تحقيق شامل
- **الإشعار:** بريد + SMS + اتصال هاتفي (للعملاء الرئيسيين)
- **الإعلام:** بيان صحفي + مؤتمر صحفي (متوقع)
- **التصعيد:** الإبلاغ للسلطات (PDPA)

#### 🔴 **المستوى 4 (أحمر) - حرج**
- **المقياس:** جميع المستخدمين متأثرين + بيانات حساسة جداً
- **الأمثلة:**
  - تسريب كلمات مرور غير مشفرة
  - تسريب جميع الوثائق المالية
  - خرق قاعدة البيانات بالكامل
  - هجوم ransomware ناجح
- **الاستجابة:** توقيف الخدمة + جلسة طارئة
- **الإشعار:** جميع القنوات + اتصال مباشر
- **الإعلام:** موقف تام + مؤتمر صحفي + بيان عاجل
- **التصعيد:** إبلاغ فوري للسلطات + استشارة متخصصة خارجية

## 4️⃣ خطوات الاستجابة (الساعات 0-72)

### **الساعة 0 (الاكتشاف)**

#### الخطوة 0.1: التأكيد الأولي
```
من قد يكتشف الخرق:
- مراقبة الأمان (تنبيهات تلقائية)
- المستخدمون (إبلاغ مباشر)
- Supabase (إشعار من الخادم)
- باحثي الأمان (إبلاغ مسؤول)

الإجراء الفوري:
1. توثيق الاكتشاف (الوقت، الطريقة، من أخبر)
2. إعادة التحقق من الحادث (هل هو حقيقي؟)
3. تحديد نطاق أولي (كم البيانات المتأثرة؟)
4. استدعاء قائد الفريق الفوري
```

#### الخطوة 0.2: الاحتواء الفوري
```
الهدف: منع التأثير من التوسع

الإجراءات:
1. عزل النظام المتأثر (إذا أمكن)
   ├─ قطع الوصول غير الضروري
   ├─ إبقاء نسخة للتحقيق
   └─ عدم حذف أي دليل

2. إذا كان خرق تطبيق:
   ├─ تحديد وإيقاف الوصول غير المصرح به
   ├─ إعادة تعيين المفاتيح المكشوفة
   └─ إجبار جميع المستخدمين على إعادة تسجيل الدخول

3. إذا كان خرق Supabase:
   ├─ الاتصال الفوري بـ Supabase support
   ├─ انتظار تعليماتهم
   └─ المساعدة في الاحتواء

4. حفظ السجلات:
   ├─ جميع سجلات الوصول (access logs)
   ├─ سجلات النظام (system logs)
   ├─ سجلات قاعدة البيانات (database logs)
   └─ لا تمحِ أي شيء
```

#### الخطوة 0.3: استدعاء فريق الاستجابة
```
الإجراء:
1. إرسال رسالة طارئة (SMS/البريد) لقائد الفريق
   "حادث أمني مكتشف - [وصف موجز] - اجتماع فوري"

2. استدعاء اجتماع طارئ (30 دقيقة لاحقاً)
   ├─ قائد الفريق
   ├─ مهندس أمان
   ├─ محامي
   └─ مسؤول التواصل

3. توثيق كل شيء من البداية
   ├─ التوقيت الدقيق
   ├─ من اكتشفه
   ├─ الخطوات المتخذة
   └─ الأدلة المجمعة
```

### **الساعات 1-6 (التحقيق والتقييم)**

#### الخطوة 1: التحقيق الفني

```
مهام مهندس الأمان:

1. تحديد نطاق الخرق:
   ├─ ماذا يمكن للمهاجم الوصول إليه؟
   ├─ كم البيانات المتأثرة؟
   ├─ كم المستخدمين المتأثرين؟
   └─ هل استُخرجت البيانات أم فقط اطُّلع عليها؟

2. جذر السبب (Root Cause Analysis):
   ├─ كيف دخل المهاجم؟
   ├─ ما الثغرة المستخدمة؟
   ├─ هل هي خطأ في الكود أو إعدادات سيئة؟
   └─ هل هناك مهاجمون آخرون؟

3. المسار الزمني (Timeline):
   ├─ متى بدأ الوصول غير المصرح به؟
   ├─ متى انتهى (إن أمكن)؟
   ├─ هل يمكن تحديد ساعات الوصول؟
   └─ هل تكرر الوصول أم مرة واحدة؟

4. جمع الأدلة:
   ├─ نسخ السجلات الكاملة
   ├─ تجميد قاعدة البيانات (نسخة)
   ├─ حفظ النسخة للتحقيق
   └─ عدم التعديل على أي شيء
```

#### الخطوة 2: التقييم القانوني

```
مهام المحامي:

1. تحديد الحد الأدنى للإبلاغ:
   ├─ هل هذا يندرج تحت قانون حماية البيانات؟
   ├─ هل يجب الإبلاغ للسلطات؟
   ├─ هل يجب إخطار المستخدمين؟
   └─ هل يوجد التزام قانوني؟

2. تحديد النطاق من الناحية القانونية:
   ├─ من يعتبر "متأثر"؟
   ├─ هل بيانات معتبرة "حساسة"؟
   ├─ هل تسري القوانين الدولية؟
   └─ متى ينتهي الالتزام بالإشعار؟

3. المسؤولية المحتملة:
   ├─ هل نحن مسؤولون عن الخرق؟
   ├─ هل هو خطأ طرف ثالث (Supabase)؟
   ├─ هل لدينا تأمين cyberinsurance؟
   └─ تقييم المسؤولية المحتملة

4. خطوات قانونية:
   ├─ إشعارات يجب إرسالها
   ├─ وقت الإرسال
   ├─ محتوى الإشعار
   └─ الاحتفاظ بسجل الإشعارات
```

#### الخطوة 3: اجتماع الفريق (الساعة 2)

```
ترتيب الاجتماع:
1. تقرير الأمان التقني (أهم المعلومات أولاً)
2. التقييم القانوني
3. تقييم التأثير على المستخدمين
4. قرار: ما مستوى الخطورة؟
5. خطة الاستجابة
```

### **الساعات 6-24 (التحضير للإشعار)**

#### الخطوة 1: تصنيف البيانات المتأثرة

```
للإشعار، حدد:

البيانات المكشوفة:
□ اسماء المستخدمين
□ عناوين البريد الإلكتروني
□ كلمات المرور (مشفرة أم لا)
□ أرقام الهواتف
□ بيانات مالية
□ صور أغراض شخصية
□ وثائق مالية
□ معرفات الأجهزة
□ عناوين IP
□ غيره: ___________

التقييم:
- هل البيانات المشفرة معروضة للخطر؟
- هل يمكن فك تشفيرها؟
- ما احتمالية الاستخدام الضار؟
```

#### الخطوة 2: صياغة قالب الإشعار

```
انظر: "قوالب الإشعار" (القسم 5 أدناه)

يجب تحتوي الرسالة على:
✓ معترف به الخرق صراحة
✓ تفاصيل ما حدث
✓ ماذا يجب أن يفعل المستخدم
✓ معلومات الدعم والاتصال
✓ الاعتذار الصادق
✓ التأكيد على التزام الأمان
```

#### الخطوة 3: الترجمة والمراجعة

```
1. صياغة بالعربية والإنجليزية
2. مراجعة قانونية
3. مراجعة لغوية
4. موافقة من قائد الفريق
5. نسخة نهائية معتمدة
```

#### الخطوة 4: التحضير التقني

```
تجهيز قنوات الإشعار:

1. البريد الإلكتروني:
   ├─ قائمة المستخدمين المتأثرين
   ├─ قالب البريد
   ├─ جدولة الإرسال الموحد
   └─ حفظ تقرير الإرسال

2. التطبيق (Push Notification):
   ├─ تصميم الإخطار
   ├─ التحقق من القنوات
   └─ اختبار المرسل

3. موقع الويب/الحالة:
   ├─ تحديث صفحة الحالة
   ├─ الإشعار الصريح
   └─ الاتصال بالدعم

4. SMS (للحالات الحرجة):
   ├─ رسالة مختصرة
   ├─ رابط لتفاصيل أكثر
   └─ جدولة الإرسال
```

```
عنوان: [تنبيه أمني حول حسابك في WAIN]

محتوى:
1. فقرة افتتاحية: اعترف واعتذر
2. ما حدث: وصف موجز
3. ماذا تأثر: بيانات المستخدم فقط

```

```
- صفحة الحالة مع الخبر

- معلومات الاتصال بالدعم
```

```
الإبلاغ إلى:
1. هيئة الحماية من البيانات الشخصية (PDPA)
   ├─ البريد: complaints@pdpa.gov.sa

   │  ├─ وصف الحادث
   │  ├─ البيانات المتأثرة

   │  ├─ الخطوات المتخذة
```

```
في حالة انتشار الخبر على وسائل التواصل:

1. المراقبة:
   ├─ مراقبة mentions على تويتر
   ├─ متابعة التعليقات على Facebook
   └─ ملاحظة أي مشاركات على Reddit

2. الاستجابة:
   ├─ توجيه الاستفسارات للبريد الرسمي
   ├─ عدم الخوض في جدالات
   └─ التأكيد على الخطوات المتخذة

3. البيان الصحفي:
   ├─ إعداد بيان موجز
   ├─ توزيع على وسائل الإعلام
   └─ الاتاحة على الموقع
```

#### الخطوة 4: فريق الدعم

```
تجهيز فريق الدعم:

1. التدريب السريع:
   ├─ شرح الحادث
   ├─ الإجابات على أسئلة شائعة
   └─ ما يمكن وما لا يمكن قوله

2. الأسئلة الشائعة (FAQ):
   ├─ ماذا حدث؟
   ├─ هل بياناتي في خطر؟
   ├─ هل كلمة مروري آمنة؟
   ├─ ماذا أفعل الآن؟
   ├─ هل سأتعرض للاحتيال؟
   └─ متى ستكون آمن مرة أخرى؟

3. قنوات الدعم:
   ├─ بريد إلكتروني: support@wainapp.sa
   ├─ الهاتف: [رقم الهاتف]
   ├─ الدردشة في التطبيق
   └─ وسائل التواصل

4. سياسة الاستجابة:
   ├─ وقت الاستجابة: أقل من 4 ساعات
   ├─ وقت الحل: أقل من 24 ساعة
   └─ تصعيد متاح للقضايا المعقدة
```

```
5. الالتزام المستقبلي

   └─ المسؤولون
```

## 5️⃣ قوالب الإشعار

### قالب 1: إشعار مستوى 1 (أخضر)

```
الموضوع: تحديث أمني بخصوص حسابك في WAIN

المحتوى:

عزيزي المستخدم،

تم اكتشاف مشكلة أمنية صغيرة في تطبيقنا، ولقد تعاملنا معها بسرعة.

ماذا حدث:
تم كشف ضعف أمني طفيف في نظام التسجيل. وقد تم إصلاحه بالكامل.

هل تأثرت بيانات حسابك؟
البيانات الحساسة (كلمة المرور، البيانات المالية) آمنة تماماً.

ماذا يمكنك أن تفعل:
✓ ليس هناك حاجة لتغيير كلمة المرور
✓ يمكنك مواصلة استخدام التطبيق بأمان
✓ إذا شعرت بأي شيء غير طبيعي، أخبرنا

للمزيد من المعلومات: privacy@wainapp.sa
```

```
- عنوان بريدك الإلكتروني (معروض)

- معرف الجهاز
❌ كلمة المرور مشفرة وآمنة

   - تغيير كلمة المرور
```

### قالب 3: إشعار مستوى 3 (برتقالي)

```
الموضوع: [عاجل] حادث أمني جاد في WAIN

المحتوى:

عزيزي المستخدم،

نكتب إليك بشأن حادث أمني جاد اكتشفناه في تطبيق WAIN.

نعتذر عن هذا الحادث ونتحمل المسؤولية الكاملة.

ماذا حدث:
في [التاريخ والوقت]، حصل مهاجم على وصول غير مصرح به إلى خوادمنا.

ما البيانات المتأثرة بالفعل:
⚠️ عنوان بريدك الإلكتروني
⚠️ اسم المستخدم
⚠️ كلمة المرور (مشفرة بـ Argon2id، لكن قد تكون معروضة للخطر)
⚠️ بيانات بعض الوثائق المالية

ما البيانات الآمنة:
✓ معظم الوثائق المالية محمية بـ RLS
✓ الصور الشخصية لم تُستخرج
✓ معرفات الأجهزة محمية

كم من الوقت استمر الوصول:
- المدة المقدرة: من [التاريخ] إلى [التاريخ]
- تم توقيفه بالكامل الآن

ماذا نفعل:
1. ✓ عزلنا النظام المتأثر
2. ✓ أغلقنا الثغرة الأمنية
3. ✓ أطلعنا السلطات (PDPA)
4. ✓ فرضنا إعادة تسجيل الدخول لجميع المستخدمين
5. ✓ نراجع جميع الحسابات للأنشطة المريبة
6. ✓ نقدم خدمة مراقبة الائتمان مجاناً لـ 12 شهراً

ماذا تفعل أنت الآن:
1. **غيّر كلمة مرورك فوراً**
   - Restart التطبيق (سيطلب تسجيل دخول جديد)
   - استخدم كلمة مرور قوية (16+ أحرف)
   - لا تستخدمها في أماكن أخرى

2. **مراقبة حسابك بنشاط**
   - تفقد بيانات الوثائق المالية
   - لاحظ أي عمليات غير معروفة
   - أخبرنا إذا شعرت بشيء غريب

3. **راقب حسابك البريدي**
   - قد تتلقى رسائل من محتالين
   - لا تضغط على روابط من رسائل مريبة
   - قدّم تقرير للجهات المختصة

4. **استخدم معرّف الائتمان المجاني** (سننشئ حساباً لك)
   - سيراقب استخدام بيانات الائتمان الخاصة بك
   - سيرسل لك تنبيهات للأنشطة المريبة

للمزيد من المعلومات:
- البريد الإلكتروني: security@wainapp.sa
- الهاتف: [رقم الهاتف 24/7]
- الموقع: https://wainapp.sa/security

نعتذر عن الإزعاج ونشكر صبرك.
فريق WAIN
```
